## 实验背景

之前你已经学习了一些常见的数字电路组件与设计方法，并进行了一些简单的组合应用。现在我们来学习一种重要的通信协议：串口通信协议，官方名称为通用异步收发器（Universal Asynchronous Receiver/Transmitter），是一种低成本嵌入式设备常见的调试以及数据传输用的协议。

> [!NOTE] 扩展：通信协议的概念
> 通信协议是指双方实体完成通信或服务所必须遵循的规则和约定。在串口通信中，信道（也就是连接我们和开发板的网络通道）中传输的内容是特定的串行数据。而这些数据是无法被我们直接阅读的，因此就需要一些特定的操作，将我们日常使用的二进制数据转换成特定的串行数据后再进行发送，以及对接收到的串行数据解码后得到二进制数据。
> 
除了编码和解码功能，通信协议同时还规定了双方通信的一些准则。即：如何知道此时信道中的数据是有效的数据、如何确定每一段数据的范围、双方的通信频率等。因此，通信协议是一段通信的核心，正确实现了通信协议也就保证了通信的正确性。

UART串口在物理层面其实就是两根数据线：TX、RX。在两个设备之间，常常以这样的方式连接：
<img src="./assets/uart/335962-fig-01.svg" alt="UART 收发交叉连接示意图" width="410" loading="lazy" />
在我们手中拿到的FPGA开发板中，其实看不到一个叫做“UART串口”的接口，取而代之的是在生活中更常见的USB接口，这是出于设计成本与面积考虑。在我们的FPGA板卡上，经常会通过**FT2232H**芯片实现USB和UART串口的集成，我们只需要将板卡连接到电脑的USB口，就可以复用这个接口进行FPGA代码的下载或者是UART协议的通信了。

## 阶段一：UART 基础收发

自己查找资料或参考正点原子/野火的教程与文档，根据UART协议内容，在FPGA上实现串口数据的接收与发送模块

> [!NOTE] 更加一般地：如何学习一种协议？
> 目前我们所接触到的大部分协议，网络上都能找到丰富的教程文档，但是未来的学习或工作中总可能遇到一些生僻的协议或者自定义的技术标准，没有人会教你这些规范如何理解。这时我们应该学会阅读**协议手册**。对于一种特定的协议或标准，定义其完整内容的手册/规范往往是最准确、最权威的。尽管这次的串口协议还没必要从官方协议手册中了解内容，但是大家要做好将来面对未知内容的心理准备。

#### 任务 1：接收字符并显示

PC 发送一个字符，FPGA 使用 8 个 LED 显示最近一次接收到的字节值。
示例：PC 发送ASCII字符 `3`，LED 显示 `0011_0011`。接收结束后，LED 应保持这一状态，直到接收到下一个字节。
> [!NOTE] 什么是ASCII码？
> 在计算机中，所有的数据在存储和运算时都要使用二进制数表示（因为计算机用高电平和低电平分别表示1和0），例如，像a、b、c、d这样的52个字母（包括大写）以及0、1等数字还有一些常用的符号（例如*、#、@等）在计算机中存储时也要使用二进制数来表示，而具体用哪些二进制数字表示哪个符号，当然每个人都可以约定自己的一套（这就叫编码），而大家如果要想互相通信而不造成混乱，那么大家就必须使用相同的编码规则，于是美国有关的标准化组织就出台了ASCII编码，统一规定了上述常用符号用哪些二进制数来表示
> （摘自百度百科）
#### 任务 2：按键发送字符串

按下 FPGA 开发板上的按键，向 PC 发送一段预先定义的 ASCII 字符串，例如：
- `I like FPGA.`
- `I like Verilog.`
至少完成**一段固定字符串**的发送，确保字符不缺失、不重复、顺序正确。也可以通过多个按键选择不同字符串。
#### 任务 3：串口回环

PC 发送数据，FPGA 将接收到的字节按原顺序返回 PC，测试单字节和连续多字节输入。

**思考**：如果 UART TX 还没有完成上一字节的发送，UART RX 又收到新字节，应该如何处理？

### 内容要求

在前面实现的UART回环基础上，我们接下来要通过串口命令实时控制FPGA内部的功能模块。

### 简易示例：呼吸灯控制器

如果你看完了前面的要求，还是不清楚怎么着手，可以结合本示例了解一下思路。

该设计的具体目标为：通过PC端发送串口指令，控制FPGA开发板上的呼吸灯模块，实现呼吸速度与花型（亮度变化模式）的动态调节。
#### 1. 指令格式定义

我们将对接收到的8位数据进行自定义编码：高2位用于控制呼吸速度挡位，低6位用于控制花型模式。通过这种方式，一条单字节指令即可同时完成速度与花型的设定。
具体定义格式见下表：

| 数据位    | 功能   | 说明                      |
| ------ | ---- | ----------------------- |
| bit7~6 | 速度挡位 | 00：慢速，01：中速，10：快速，11：极速 |
| bit5~0 | 花型模式 | 000000~111111 共64种花型    |

例如，指令 `8'b00_111000` 表示：速度挡位为00（慢速），花型模式为 `111000`（对应的LED灯效）。

#### 2. 发送命令进行控制

在实际操作中，我们通常通过串口助手发送字符来控制FPGA。例如，在串口助手中输入字符 `8`，其对应的ASCII码为 `8'b0011_1000`（即十六进制 `0x38`）。

<img src="./assets/uart/Pasted%20image%2020260329111441.png" alt="串口助手发送 ASCII 字符示例" width="554" loading="lazy" />
当FPGA接收到该字节后，我们需要对其进行解析：

- 高2位 `2'b00` 表示选择慢速挡位
- 低6位 `6'b111000` 用于控制LED花型

**注意**：串口助手可以切换显示模式。若以十六进制形式发送 `0x38`，则接收到的数据同样为 `8'b0011_1000`，解析逻辑不变。
<img src="./assets/uart/Pasted%20image%2020260329111523.png" alt="串口助手十六进制发送示例" width="544" loading="lazy" />
#### 3. 指令解析模块设计参考

以下是一个简单的指令解码模块主要逻辑示例，用于从接收到的串口数据中提取速度挡位和花型信息，并产生对应的控制信号：

```Verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        speed_ctrl <= 2'b01;      // 默认中速
        pattern_ctrl <= 6'b000001; // 默认花型
    end else if (rx_valid) begin
        // 解析接收到的8位数据
        speed_ctrl <= rx_data[7:6];   // 高2位为速度挡位
        pattern_ctrl <= rx_data[5:0]; // 低6位为花型模式
    end
end

// 根据速度挡位计算分频计数值
parameter CLK_FREQ = 50_000_000; //系统时钟频率
reg [31:0] pwm_period;

always @(*) begin
    case (speed_ctrl)
        2'b00: pwm_period = CLK_FREQ / 1;      // 1Hz 慢速
        2'b01: pwm_period = CLK_FREQ / 2;      // 2Hz 中速
        2'b10: pwm_period = CLK_FREQ / 4;      // 4Hz 快速
        2'b11: pwm_period = CLK_FREQ / 8;      // 8Hz 极速
        default: pwm_period = CLK_FREQ / 2;
    endcase
end
```
